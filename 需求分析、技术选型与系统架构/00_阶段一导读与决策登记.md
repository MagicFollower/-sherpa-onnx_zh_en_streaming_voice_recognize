# 00 阶段一导读与决策登记

## 1. 文档定位与证据口径

本组文档形成本地离线实时语音识别项目第一阶段研究基线，可供第二阶段实现及独立验收使用。
研究资料访问日统一为2026-09-21；本轮只归档已完成研究，不重新进行行业搜索。
文档基线为D1，应用协议名称为LASR，版本为1.0；版本含义见05_音频与实时通信协议.md第2节“版本、标识与传输约定”。
本阶段没有业务代码、模型下载、依赖安装、证书配置、服务启动、测试、构建或性能结果。
独立文档核查属于后续任务，不把本次写作描述为已通过核查。

以下标签贯穿全部文档，不能相互替代：

| 标签 | 含义 | 使用边界 |
| --- | --- | --- |
| 用户确认 | 用户明确批准的产品约束 | 改变此项须重新确认 |
| 本机观察 | 前期只读环境检查所得 | 不是目标机器要求，也不是本轮复测 |
| 文献事实 | 官方文档、模型卡、论文或公开集成记录 | 受版本、作者自评及环境限制 |
| 建议基线 | 为使下一阶段可实施而提出的具体设计 | 不是用户逐项确认，须按验收调整 |
| 待实测 | 尚无本项目数据或兼容性证据 | 不得写成可用、达标或生产认证 |

证据另按性质区分：E1为固定论文版本或固定提交，E2为动态官方文档与模型卡，E3为公开产品或项目集成，E4为本项目实验。
目前E4为空；E3仅能证明存在集成，不证明中文实时SLA或客户规模。
带版本标签的发布页不等于所有附属制品已做哈希冻结；没有冻结commit的网页均按动态上游管理。

## 3. 用户确认与决策登记

用户确认：普通话为主且支持中英混说；普通无独显CPU电脑优先；电脑运行后端、手机通过LAN浏览器访问。
用户确认：移动端按住按钮；PC鼠标或空格按住；一轮一个气泡、实时更新；实时体验优先。
用户确认：接受手机安装并信任本地CA；采用可信HTTPS和同源WSS；运行期无互联网依赖与云识别回退。
用户确认：第二遍精修默认关闭，必须在目标CPU上同时证明收益和预算合格后才考虑启用。
用户确认：按本目录八篇专题完成首阶段完整研究，不扩写业务代码或额外报告。

| 决策ID | 当前决定 | 性质与理由 | 改变条件 |
| --- | --- | --- | --- |
| D01 | A主选sherpa-onnx双语Streaming Zipformer | 建议基线；原生流式与Windows CPU路线清晰 | 质量或稳定性不合格必须重新选择 |
| D02 | B保留FunASR Paraformer两遍挑战 | 建议基线；Windows原生服务存在但制品年代有差异 | 同语料质量收益可重复且全部资源门槛通过 |
| D03 | 第二遍声学精修关闭 | 用户确认；实时优先 | 经质量、延迟、内存、长稳联合放行 |
| D04 | Vue 3、TypeScript、Vite与原生浏览器API | 建议基线；单页面交互和协议类型清晰 | 若产生已验证的维护或兼容障碍再评估 |
| D05 | FastAPI、Uvicorn单网络进程与独立常驻worker | 建议基线；网络与CPU推理隔离 | 多路需求确认后重新做容量设计 |
| D06 | 同源HTTPS、API、WSS；受控LAN本地CA | 安全原则用户确认，具体工具为建议 | 公网或企业场景须升级信任与运维体系 |
| D07 | 单机最多一路活动识别，其他连接明确拒绝 | 建议基线；不按CPU核数复制模型 | 并发需求与目标CPU压测共同确认 |
| D08 | 不保存音频或正文，不跨客户端广播 | 建议基线；隐私与最小存储 | 历史、导出或同步功能另行确认 |
| D09 | 普通松手stop，失焦、后台及异常输入cancel | 建议基线；避免无法保证的后台录音 | 有明确替代交互及真机证据才调整 |
| D10 | 16kHz单声道PCM16LE，20ms网络帧 | 建议基线；网络帧不同于模型chunk | 以端到端延迟与兼容性实验调整版本 |
| D11 | 本机配对口令换安全会话cookie | 建议基线；无数据库账户系统 | 多用户权限需求出现时重新设计 |
| D12 | ITN保持关闭，标点作为有界可降级后处理 | 建议基线；避免数字误改和授权缺口 | 制品许可、Windows兼容和专项质量均通过 |

A的具体权重为sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20。
官方INT8示例采用量化encoder、浮点decoder、量化joiner和tokens，不能改写成全INT8已经验证。
约200MB只描述相关模型组件的磁盘量级，不代表进程RSS或最低内存。
A是约束下的优先候选，而非已经证明的世界最准方案；A质量不达标时不能因速度快而放行。

| U01 | 实际目标CPU与手机型号未知，影响速度和兼容性 | 确认设备清单并按07_测试验收与性能基线计划.md“设备、环境与制品冻结”分档实验 | 至少一个无独显目标档位和实际手机通过 |
| U02 | A的手机混说、数字和轻口音质量未知 | 冻结验收集，中文CER、英文WER分别计分 | 满足07_测试验收与性能基线计划.md第3节“语料、指标与质量门槛” |
| U03 | B旧Windows EXE与后续源码修复对应关系未知 | 追溯二进制来源、版本、哈希及跨轮用例 | 可追溯且flush、串轮、长稳全部通过 |
| U04 | 主选标点及ITN完整授权链未冻结 | 逐制品保留权重许可、来源和revision | 标点许可完成才能启用；ITN另过数字专项 |
| U05 | 手机本地CA信任、权限与后台行为有厂商差异 | 真实iOS、Android及实际浏览器验证 | 安全上下文、WSS、取消和迟到授权通过 |
| U06 | 热词是否必需及词表未确认 | 收集领域词，比较greedy与modified_beam_search | 收益足够且误插入、CPU和延迟不过线 |
| U07 | 完全离线安装包未被用户要求 | 区分可联网准备与断网安装两种交付需求 | 明确包范围和依赖再承诺离线安装 |
| U08 | 准确率、内存绝对预算仍属建议 | 用业务样本和目标8GB档位协商冻结 | 07_测试验收与性能基线计划.md“延迟、RTF、资源与长稳基线”预算在实验前批准 |
| U09 | 配对口令、会话过期和设备管理体验未实机验证 | 按06_局域网HTTPS与离线交付运维.md“最小配对与会话鉴权规格”设计负例 | 未授权无法连接和占用推理，操作可恢复 |
| U10 | 字幕编辑、持久历史与辅助点按未纳入范围 | 如有需求另提范围变更及隐私设计 | 不在当前按住模式中暗加后台录音或存储 |
