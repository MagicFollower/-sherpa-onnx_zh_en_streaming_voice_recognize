# 04 系统架构与数据流

## 1. 架构边界与不变量

文档基线D1、协议LASR 1.0；本篇为建议架构，不是已完成的系统。
普通CPU、LAN浏览器、运行离线与精修默认关闭来自用户确认；进程、队列、端点与认证细节属于设计基线。
对应需求R02、R05、R09至R16、R18至R20；验收见07_测试验收与性能基线计划.md第5节“A01至A20验收矩阵”。
系统坚持单机、一个网络进程、一个常驻推理worker、最多一路活动识别。
一个utterance_id绑定一个连接session_id和一张卡片；只有持有该轮所有权的连接能收结果。
网络进程是外部终态的唯一提交者；worker只返回候选事件，不直接向浏览器发final。
任何一层容量不足都显式拒绝或终止，不无限排队、不静默丢采样、不把异常包装成成功。
不引入数据库、Redis、微服务、默认WSL或默认Docker，不为高配机器复制多份模型。

## 2. 部署拓扑与模块职责

```text
PC浏览器或手机浏览器
    HTTPS静态页面与鉴权API / 同源WSS
    Vue状态机 → AudioWorklet → 实际采样率转换 → PCM网络帧
                         ↓ 可信LAN TLS
单网络进程：FastAPI + Uvicorn TLS
    Host与Origin校验 → cookie鉴权 → 连接会话 → 轮次协调器
    音频校验与有界入队 → 外部ACK、partial和唯一终态
                         ↓ 有界IPC，不开放LAN端口
独立常驻推理worker
    模型加载 → 独立流状态 → chunk解码 → 内部segment累计
    stop flush → 可选标点 / 获准第二遍 → 候选终稿
                         ↓
候选事件返回轮次协调器，由其原子决定外部终态
```

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 页面状态机 | 输入所有权、卡片、权限竞态、取消意图和错误恢复 | 不推断模型内部segment就是用户final |
| AudioWorklet及重采样 | 样本时钟、边界、抗混叠与尾帧排空 | 不发送JSON、不直接持有配对凭据 |
| 浏览器发送器 | seq、总样本、发送水位、stop排序 | 不在重连后重放旧PCM |
| 网络服务 | TLS、静态资源、API、WSS校验与连接数限制 | 不在事件循环运行声学推理 |
| 轮次协调器 | 全局槽位、终态仲裁、超时、ACK和资源释放 | 不直接假造识别正文 |
| 推理适配器 | 统一模型流、端点和flush语义 | 不把厂商is_final透传成整轮终态 |
| worker | 常驻模型与单轮状态，返回进度及候选结果 | 不保存录音，不持有浏览器cookie |
| 本地运维入口 | 配对口令、配置、模型资产和证书维护 | 不提供未确认的公网管理面板 |

Node只用于前端构建；发布包中的静态JS、CSS、字体和worklet由本机同一HTTPS源提供。
默认直接用Uvicorn TLS，避免为受控LAN引入反向代理；如未来改为代理，须重新检查Origin、Host、转发头和证书边界。

## 3. 最小接入控制与接口边界

LAN并非可信身份边界，Host和Origin白名单只是防重绑定及跨站的措施，不能替代会话鉴权。
建议本机生成一次配对口令，经HTTPS交换随机安全cookie；详细参数与运维步骤以06_局域网HTTPS与离线交付运维.md第4节“最小配对与会话鉴权规格”为准。
配对口令不写在URL、localStorage、前端包或常规日志中；不能把CA私钥当作客户端认证材料分发。
cookie只保存在浏览器安全cookie存储，网络层仅保存其摘要和有效期等元数据；worker不接触它。
每次WSS握手同时检查有效cookie、精确Origin和Host；鉴权在WebSocket升级与识别容量分配之前完成。
应用start没有额外登录口令字段，它只在已鉴权连接上申请一轮资源，避免与首次配对协议冲突。
同源写接口校验Origin且只接收预期媒体类型，不使用宽泛跨源允许策略。

| 建议端点 | 鉴权与语义 | 数据最小化 |
| --- | --- | --- |
| GET / | 页面入口，可显示配对界面 | 静态包不含密钥和本机绝对路径 |
| POST /api/pair | 同源HTTPS；一次口令换会话cookie | 不回显口令，不返回模型内部路径 |
| POST /api/logout | 有效cookie；撤销会话并清理其连接 | 不要求数据库；页面清空正文 |
| GET /api/status | 有效cookie；模型就绪、协议及容量状态 | 不公开其他客户端正文和标识 |
| GET /health | 可匿名，仅最小存活状态 | 不输出环境变量、模型路径或设备标识 |
| WSS /ws | 有效cookie、Origin、Host与连接配额 | 一个连接获得新的session_id |

鉴权cookie标识浏览器授权，而session_id标识一次WSS连接；重连必须生成新session_id，两者不能混同。
默认最多4个有效配对会话和4条WSS连接，每个cookie最多一条WSS；多页第二连接明确拒绝，不抢占旧连接。
注销、会话到期或本机撤销授权会关闭连接；活动轮按协议错误或取消仲裁释放，不继续后台识别。
已经提交的终态不能因注销再改成另一个终态；客户端注销仍清空页面正文。

## 4. 启动、运行与模型生命周期

### 4.1 启动顺序

读取本地配置、校验证书和制品清单，明确模型路径必须是本地绝对或相对受控路径。
启动一个worker，显式选择CPU执行提供器，限制解码和底层数值库线程，避免嵌套线程争用。
worker加载一次模型与token表，必要时执行本地暖机；模型不可用则保持服务“未就绪”，不能首次请求临时联网下载。
网络层只在worker报告可用后允许start进入ready；页面可先展示状态，但“网络可连”不等于“识别可用”。
模型权重在服务生命周期常驻，流缓存每轮新建；重新加载模型不复用上一轮状态。
模型初始化失败不循环无限重启；记录无正文诊断并等待运维修复。

### 4.2 正常数据流

权限通过且仍按住 → start → 槽位与流状态建立 → ready → 才打开采集门。
PCM先通过版本、UUID、序号、帧长和总样本校验，再进入统一有界预算；此时可推进received ACK。
worker完成对应音频的真实解码消费后推进processed ACK，不以网络read完成冒充处理完成。
worker把已完成segment与当前segment草稿拼成整轮候选，协调器分配严格递增revision并发送完整partial。
VAD内部端点允许重置内部流并开启下一segment，但所有segment仍保留外层UUID。
正常松手后stop声明最后序号和样本数；协调器确认收齐，再通知worker最终flush。
flush完成且启用后处理已成功或明确降级后，协调器提交唯一final；此后同轮候选全部作废。

### 4.3 取消与worker故障

cancel先在协调器原子记录终态，再向worker发送高优先级取消标识并清除队列中的该轮输入。
取消标识走独立控制通道，不能排在2秒音频后面；即使推理库不能即时打断，迟到输出也因generation失效而被丢弃。
worker确认释放前不把槽位交给下一轮；超过2秒清理期限则隔离或重启worker，并保持模型未就绪。
worker崩溃使当前轮终结为WORKER_FAILED，不能把最后partial作为完整final；模型重载期间拒绝新start。
网络断连时清理连接拥有的轮次；重连不恢复旧流，清理未完成前返回MODEL_NOT_READY或BUSY。
正常服务关闭先拒绝新start、取消活动轮并释放音频和会话，再结束worker；不进行后台无限精修。

## 5. 容量、有界IPC与背压

所有数值均为待验证设计参数；协议水位的规范定义在05_音频与实时通信协议.md第8节“水位、超时与容量参数”。
活动槽位从接受start持续到终态提交且worker清理完成，包含准备、录音、排空、finalizing和取消清理。
其他连接收到BUSY，不建立隐藏等待队列；单机1路不是每个连接1路。
每条WSS最多一个未结束轮次，恶意并发start不能绕过全局槽位。

| 通道或状态 | 建议硬边界 | 溢出处理 |
| --- | --- | --- |
| 全链路未处理音频 | 32000样本，即2秒 | 明确OVERLOADED并结束；不静默丢帧 |
| 音频IPC | 最多100个常规20ms帧，且受全链路样本预算约束 | 入队失败立即回报协调器 |
| 控制IPC | 8项，取消另用可覆盖的原子标志 | 不让cancel被音频堵塞；异常则故障回收 |
| worker结果IPC | 16项；未发partial可被更高revision合并 | 终态候选保留专用槽，不因草稿占满丢失 |
| 单连接发送队列 | 最多32项且不超过256KiB | 合并旧partial；仍阻塞则关闭慢客户端 |
| JSON控制消息 | 每条最多16KiB UTF-8 | 拒绝过大消息，不解析无限文本 |
| 终态重传缓存 | 每连接最多16轮且30秒 | 淘汰后旧ID返回STALE_UTTERANCE |

2秒预算包含已采样未发送、网络未处理、IPC排队和正在计算尚未ACK的音频，不允许每层各积压2秒后相加。
样本预算是逻辑音频进度上限；不同层短暂复制导致的物理内存另纳入RSS测量，不能用PCM大小当总内存。
worker从队列取走不等于已处理，正在解码的chunk仍计入未处理预算。
客户端用产生样本数减processed_samples估计端到端积压，并用bufferedAmount补充监视实际发送缓存。
服务端用接收样本数减处理样本数限制已知积压；未发送音频只能由客户端限制，双方都不可省略。
0.5秒水位时告警并减少非必要草稿频率或未开始的可选增强，不降低采样率或抛弃中间PCM。
客户端持续回压最终超过2秒时中断当前轮，不能在后台积压到用户松手后再等待数十秒。

## 6. 数据生命周期与隐私销毁点

| 数据 | 所在位置 | 保留与销毁 |
| --- | --- | --- |
| 实际麦克风采样与重采样状态 | 浏览器音频线程 | 本轮有界缓冲；正常drain或cancel后释放 |
| 待发送PCM | 浏览器发送器 | ACK预算内短留，不为重连保留；断连清空 |
| 已接收未消费PCM | 网络与worker IPC | 消费或取消后释放，受2秒总预算约束 |
| 模型流缓存 | worker | 每轮独立；终态或故障清理，不跨客户端复用 |
| 两遍整轮PCM | worker，仅获准启用时 | 最多60秒、1920000字节原始PCM；终态即释放 |
| 模型权重与运行时arena | worker | 服务期间常驻，属于资源预算，不是用户录音历史 |
| partial与segment文字 | worker及协调器 | 仅本轮；取消或终态后清理，只保留有限终态缓存 |
| 终态正文缓存 | 网络进程 | 每连接16轮、30秒，连接关闭即销毁 |
| 页面卡片正文 | 当前浏览器内存 | 最多50卡；清空、注销、刷新或关闭销毁 |
| 配对会话摘要 | 网络进程内存 | 有效期、撤销或服务重启后失效 |
| 已见UUID墓碑 | 网络进程内存，无正文 | 每连接最多1000项；到限空闲轮换session，断连销毁 |
| 诊断元数据 | 有界本地日志 | 默认最多10MiB、7天；不含音频、正文和密钥 |

不使用localStorage、IndexedDB或服务端数据库保存识别正文；静态资源缓存不等于允许缓存API正文。
用户点击复制会进入系统剪贴板，属于明确外部操作，不能保证其他应用不读取。
“不落盘”指应用不主动持久化内容，不承诺操作系统交换、浏览器恢复和第三方终端工具的物理擦除。
若实验需留存原始音频，应在单独获批的验收数据流程中处理，不与产品默认日志混在一起。

## 7. 适配层与降级边界

主选A的VAD或端点逻辑仅影响内部segment，不改变用户按住轮次和外部final数量。
B的2pass-online形成草稿，2pass-offline可以替换内部段落，但须等用户stop及整体flush后才给整轮final。
网络层统一维护revision、取消代数、last_seq和total_samples，不依赖某个模型服务的字段命名。
精修默认关闭；启用时先有完整的一遍候选，再在有界预算内决定是否采用第二遍。
标点超时或失败可返回完整无标点原文，必须标记对应降级原因；不得在final之后静默补标点。
一遍声学处理失败、尾帧缺失、样本错序或整轮超时属于错误，不允许用降级理由掩盖内容不完整。
如果增强调用无法及时取消，需要隔离执行或重启worker；前台final已发也不能导致下一轮共享被占死的状态。

## 8. 可观测性与后续实现入口

每轮记录无正文的开始、ready、首个partial、stop收讫、处理ACK、终态及清理时间，使用单调时钟。
客户端端到端指标和服务端计算指标分开；不同设备单调时钟不能直接相减。
可观测项包括队列样本数、全局槽位、模型就绪、取消回收耗时、RSS、CPU和错误码计数。
本机环境只读观察见00_阶段一导读与决策登记.md第6节“本机观察与适用边界”；不能用该高配环境推定目标CPU资源。
