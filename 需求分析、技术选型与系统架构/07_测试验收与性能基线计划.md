# 07 测试验收与性能基线计划

## 1. 本篇性质与验收原则

本篇是第二阶段及后续阶段的实验与验收计划，不是本轮执行记录；当前没有任何测试、构建或性能通过结果。
文档基线D1、协议LASR 1.0；R01至R20定义在01_需求规格与范围边界.md第3节“需求登记与验收映射”，A01至A20与其直接对应。
所有数据量、阈值、设备档位与持续时间都是建议目标或待实测条件，应在实验前批准并冻结。
用户确认的是普通CPU、混说、实时优先、按住交互和离线边界，不是本篇全部具体数字。
先通过许可与正确性门槛，再比较速度；准确率不合格的A不能因更快而放行。
B只有在同语料同硬件取得可重复质量收益且延迟、内存、稳定性不越线时才替换A或启用第二遍。
失败、超时、取消与缺失partial必须保留在结果中，不通过只统计成功样本美化P95。
独立验证人员可依据本篇设计用例；本轮文档作者不兼任实际测试或代码审查。

## 2. 设备、环境与制品冻结

### 2.1 试验档位

| 档位 | 建议配置 | 用途与限制 |
| --- | --- | --- |
| CPU-A | 4核、8GB、无独显 | 普通CPU优先的关键试验档位，不是已证实最低配置 |
| CPU-B | 6核、16GB、无独显 | 观察CPU与内存余量，不允许掩盖CPU-A失败 |
| 参考机 | Ryzen 9 5900X、95.93GiB内存、RTX 3080 Ti | 只作为前期观察和辅助比较；CPU实验显式不用GPU |
| 手机-A | 实际Android与Chrome | 型号、版本、CA与工作资料情况待登记 |
| 手机-I | 实际iPhone与Safari | 型号、iOS版本、根证书完全信任待登记 |
| PC浏览器 | 实际Windows Chrome和Edge | 记录版本、麦克风、输入法及音频设备 |

仅限制高配机线程不能完全模拟普通电脑的缓存、内存带宽、功耗和散热，不能替代真实目标档位。
同一候选实验固定电源模式、后台负载、浏览器版本、LAN路由、Wi-Fi位置和采集设备。
至少区分冷启动模型加载、已加载首轮、持续热运行三种状态，不把预热效果隐藏在结果中。
CPU档位实验显式选择CPU执行提供器，不以安装了GPU但未记录调用方式的结果声称CPU合格。

## 3. 语料、指标与质量门槛

### 3.1 数据建议与划分

建议300至500条录音、8至12名说话人，覆盖普通话主体、自然中英混说和真实手机麦克风；这是起始规模，不是统计充分性的保证。
尽量覆盖不同性别、年龄段、自然语速和轻口音，不把随机朗读标准短句当作全部业务场景。
建议60%用于调参、40%冻结验收；按说话人分离，且同一句或近重复句不能跨两侧泄漏。
样本应包含1至5秒、5至15秒、15至60秒三个轮长组，较长轮次单列资源与终稿延迟。
建议安静普通话约40%、混说约30%、噪声与轻口音约20%、数字或领域强化约10%，可多标签但报告分组需明示。
另外建立不少于30条静音、环境噪声和极短误按负例，不把空参考强行加入CER分母。
数字集覆盖金额、小数、日期、手机号、编号、英文缩写、单位与连续英文单词；关键字段保留人工标注边界。
热词集同时包含应命中词与不该触发的近音词、普通词，避免只测正例召回。
两名标注者核对关键文本及数字，对分歧仲裁；口吃、重复、语气词是否保留在实验前统一。
每条记录语言片段、有效语音起点、轮长、说话人匿名编号、噪声类别、设备与网络组，不记录无关身份信息。
参与者需明确同意采样与保存期限；验收语料的存储规则单独获批，不改变产品默认不存录音。

### 3.2 规范化与分词

基础ASR评价采用冻结参考文本；统一Unicode NFKC、空白规则和英文字母大小写，保留语义差异。
中文按汉字计token，英文按词计token；英文连字符、撇号、缩写的切分规则须版本化，不能随候选改变。
建议英文内部撇号保留为一个词、连字符拆分、独立字母缩写按参考所写词形计；专有缩写另建固定表。
标点从基础ASR质量计分流中去掉，但在单独标点指标中保留；不能通过删词或同音替换提高成绩。
混说先在完整混合token序列上做确定性编辑对齐，再按参考token的语言归属统计替换和删除，插入按输出token归属统计。
跨语言替换计入参考语言的替换错误，不能把错误英文或中文先过滤掉而遗漏；出现对齐平局使用固定优先级规则。
汉字子集计CER，英文词子集计WER，分别报告分母；没有英文参考的组不计算除零WER，而报告英文幻觉插入次数。
数字、单位和其他token保留在完整对齐中并单独分组；不靠只统计汉字来忽略数字错误。
评测归一化不是产品ITN；产品仍默认保持原文，评测不得用无限制数字改写掩盖错误。

### 3.3 指标定义

中文CER为中文替换数、删除数和插入数之和除以参考汉字数，报告百分比。
英文WER为英文替换数、删除数和插入数之和除以参考英文词数，报告百分比。
同时报告按全部token汇总的micro结果和按说话人或设备的分组结果，避免高频说话人主导结论。
数字exact-match为完全正确字段数除以标注字段总数；金额符号、小数点、前导零和单位都按冻结规则处理。
可另报告经有限且预先批准规则规范化的数字准确率，但必须同时保留未经改写的原始字段exact-match。
热词recall为应出现且正确识别的次数除以应出现次数；误插入率为负例轮次中出现未经表达热词的轮次比例。
标点按允许标点类别与token边界计算precision、recall及F1，不能用加标点后的CER替代。
静音幻觉为无有效语音轮次产生非空final的比例，同时保留误报文本长度的匿名统计。
取消轮次不参与文本准确率，但要计取消成功、资源回收、迟到结果和交互完整性。
失败轮次单独计失败率；质量总报告必须披露未返回终稿的样本数，不只列成功轮的CER。

### 3.4 建议质量门槛

| 项目 | 建议放行目标 | 使用条件 |
| --- | --- | --- |
| 安静普通话 | CER不超过10% | 独立验收集；同时看说话人分组 |
| 噪声或轻口音普通话 | CER不超过20% | 噪声类型与强度必须登记 |
| 混说中的英文 | WER不超过25% | 不与中文CER混为一个指标 |
| 数字字段 | 原始exact-match至少95% | 关键金额或编号仍要求人工复核，不自动执行动作 |
| 热词，若启用 | recall至少90%，负例误插入不超过1% | 必须同时满足CPU和英文质量门槛 |
| 标点，若启用 | F1至少80%，无正文语义增删 | 许可和延迟先通过；失败可保持关闭 |
| 静音负例 | 冻结负例集非空final为0 | 有限样本上的门槛，不宣称真实世界零幻觉 |
| 跨轮正确性 | 零串话、零重复卡片、零迟到污染 | 任一出现均阻断放行 |

以上均待用户批准及实测；没有现成测试值，不得以降低阈值方式让某候选事后“通过”。
建议对按说话人配对的差值做95%置信区间，样本过少则明确不确定，不用单次更低CER宣称稳定优胜。
若B替换A或开启两遍，建议核心质量项相对改善至少10%，置信区间支持正收益且其他项不劣化；同时通过第4节资源门槛。

## 4. 延迟、RTF、资源与长稳基线

### 4.1 客户端时间口径

首字延迟起点为采集侧有效语音首样本，终点为客户端收到并渲染首个非空partial，使用同一客户端单调时钟关联。
语音起点通过带标注音频或可核对的采集样本索引确定，不能随候选用不同VAD阈值决定起点。
按住到ready、权限等待和ready到说话的静音分别统计，不混入首字以掩盖启动成本。
如果一轮直接final且没有非空partial，记为“缺失partial”；不能将final时间改名为已满足实时草稿。
stop-to-final起点为正常松手或60秒自动stop，终点为客户端接受完整终稿；包含drain、发送、flush与启用后处理。
服务端收到stop到final只是内部拆分指标，不替代用户感知终稿等待。
P95按每组观测值排序取向上取整的95%位置；每组建议至少100次有效轮次，不足时标记样本量限制。
同时报告P50、P95、最大值、失败率、超时率和缺失partial率；不能仅展示成功样本的分位数。

### 4.2 处理耗时与RTF

RTF为实际模型处理耗时除以输入音频时长，分别报告流式声学、flush、标点和第二遍开销。
真实处理耗时应累计worker实际计算区间，排除等待下一块实时音频和IPC空闲等待，不排除模型计算导致的阻塞。
另用不按实时速度投喂的同格式离线回放测吞吐RTF，必须标明这是吞吐实验，不是端到端用户延迟。
不能用整轮录音墙钟时长除以音频时长得到约1就宣称模型计算RTF合格。
初始加载与暖机单列；不得把模型第一次加载时间摊入8小时后隐藏冷启动体验。
跨设备客户端与服务端时钟不可直接相减；服务端事件拆分用服务端单调时钟，端到端用客户端时钟。

### 4.3 建议资源与体验目标

| 指标 | 建议目标 | 备注 |
| --- | --- | --- |
| 首个非空partial | P95不超过1.5秒 | 缺失partial单列；有效发声5秒以上轮次建议非空partial覆盖至少99% |
| 15秒内轮次stop-to-final | P95不超过2秒 | CPU主路径，包含启用后处理 |
| 超过15秒至60秒轮次 | P95不超过4秒 | 独立长轮目标，不能套短轮结论 |
| final硬保护 | 松手起15秒 | 到期必须终止，不属于正常体验目标 |
| 计算RTF | 必须小于1，余量目标不超过0.5 | 每个CPU档位分别报告 |
| 音频积压 | 不持续越0.5秒警戒，绝不突破2秒硬线继续缓存 | 达线按协议中断，不能静默丢帧 |
| 8GB档位进程RSS合计 | 稳态目标不超过2GiB，峰值不超过3GiB | 网络与所有worker合计，不用权重大小替代 |
| 系统余量 | 目标至少保留2GiB可用内存，避免持续换页 | 与实际OS和其他负载共同记录 |
| CPU占用 | 整机持续平均目标不超过70% | 额外余量目标，不替代RTF或P95 |
| 取消回收 | 正常情况下2秒内清理；卡死则隔离/重载worker | 未清理不得分配新轮 |
| 无故障注入正常轮 | 建议成功率至少99%，协议污染为0 | 超时、模型错误均计失败 |

绝对内存和CPU余量仍待目标设备与业务批准，B不能使用不同预算却标为同条件优胜。
每秒采样网络进程与worker的RSS、私有内存、CPU、队列水位；不按线程数相加伪造物理核性能。
2小时冒烟、8小时长稳和至少1000轮开始、正常结束、取消、重连组合为建议计划，可拆分执行并保留各自统计。
建议预热后最后一小时空闲稳态RSS比第一小时空闲稳态增长不超过10%，同时不突破绝对预算且无持续上升趋势。
运行时arena保留内存不一定是泄漏，但必须形成平台；不能借此解释每轮无界增长。
8小时期间仍遵守30分钟空闲、8小时绝对会话有效期，到期重新配对可作为计划用例，不关闭安全机制凑长稳。

## 6. 关键执行流程与故障注入计划

### 6.1 推荐执行顺序

1. 检查冻结制品、许可与协议配置，发现无授权或版本不明即暂停相关候选。
2. 做单轮协议和重采样确定性检查，再接真实麦克风；不先用长稳掩盖基础字节错误。
3. 做真实PC与手机交互、证书及配对正负例，再开展模型质量比较。
4. 在调参集决定线程、解码和端点，冻结后才接触验收集。
5. 分档测准确率、延迟、资源和背压，再进行2小时与8小时稳定性计划。
6. 断WAN冷启动验收及更新回退演练通过后，汇总联合放行条件。

### 6.2 音频与终态确定性用例

构造具有可识别计数的源样本，分别覆盖44.1kHz、48kHz、16kHz和多声道下混，验证输出时长和累计采样数。
使用只在末尾出现的短词检查尾音；同时比对源截止点和发送样本，不能只听起来完整就认定没有额外采集。
验证0帧stop为last_seq负1、total_samples为0；短帧发送后再发音频必须被拒绝。
模拟seq重复、跳号、UUID混合大小端、错误header_length、reserved非零和消息长度不符。
将cancel分别安排在ready之前、音频入队后、flush中、终态提交前后，检查唯一终态和本地丢弃意图。
终态过30秒缓存或超过16轮后请求旧ID，应得到STALE_UTTERANCE；不能重新开始同UUID。
同连接达到1000个不同轮次后空闲轮换session，不能无限增长墓碑集合。

### 6.3 故障与背压

限制worker处理速度至明显落后，观察0.5秒警戒与2秒硬线；队列不能按层堆成多倍2秒。
限制客户端接收或网络上行，检查bufferedAmount、合并partial与慢客户端关闭；不能牺牲terminal消息后继续假运行。
让worker进程异常退出或模拟推理不响应，检查错误、2秒清理保护、模型未就绪与重载，不把旧结果送到下一轮。
在一台设备录音时另一台申请start，必须立即BUSY且不影响第一台；未授权连接不得先占容量。
模拟证书不可信、口令错误、会话到期、注销、null Origin及Host不在名单，检查无敏感错误内容。
所有故障注入均在明确授权的本地试验环境中开展，本阶段未执行。

### 6.4 真正运行离线

保留LAN和电脑本地服务的可达性，切断WAN出口；关闭手机蜂窝、热点、VPN及其他可访问互联网的旁路。
清理页面缓存、关闭并重新打开页面，重启本地服务和模型，确保不是先前缓存或热模型掩盖外部依赖。
重新完成本地配对并录音，检查前端字体、worklet、模型、标点及依赖没有外部下载或认证请求。
通过请求观察与网络边界共同证明应用不依赖WAN；浏览器自身背景流量应与应用请求分开归因。
不能只使用浏览器开发者工具的Offline开关，因为它可能连本地LAN一起切断，也不能只断电脑网线同时让手机走蜂窝。
该测试只证明预先准备好的系统可离线运行，不自动证明新电脑无网络可完成全套安装。

## 7. 结果记录、切换判据与未决项

每次后续实验应保留运行标识、R/A映射、制品及配置、硬件、样本分组、指标、失败数和简短原因，不把正文加入普通诊断日志。
当前本组不创建实验结果文件或额外报告，所有指标结果状态统一为“未执行、待实测”。
模型比较应展示A、B流式基础、B两遍的同条件结果，不能用A手机噪声录音对比B公开干净语料。
质量收益采用配对语料和多次运行；性能至少重复3轮并说明波动，准确率变化须定位是否模型或输入链路变化。
A满足全部P0门槛时可作为下一阶段发布候选；不是仅完成模型加载就可交付。
B只有质量改善可重复、许可与制品可追溯、延迟与内存不破预算、长稳和终态正确性都通过才获得替换或精修资格。
若增强不合格但基础路径合格，保持增强关闭并明确状态；一遍结果本身失败不能以降级名义放行。
如果A、B均不合格，列出失败组和瓶颈，重新讨论语料、配置、候选或需求预算，不偷偷切GPU或云端。
实际手机、最低可用CPU、最终精度预算、ITN和完整离线安装包仍有缺口，处理条件见00_阶段一导读与决策登记.md第5节“未决项与放行责任”。
